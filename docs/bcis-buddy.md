# BCIS Buddy

BCIS Buddy is a renderer companion mounted only inside the authenticated Electron workspace. Its layered SVG has a shaded BCIS cap and Wi-Fi emblem, padded blue headphones, large highlighted eyes with eyelids, a shaped chibi face, a detailed uniform and cape, articulated gloves, and cuffed boots. Head turn, ambient head motion, torso, torso ambience, shoulder ambience, arm pose, forearm art, individual legs, face, eyes, eyelids, and mouth are distinct vector layers. The illustration remains original local SVG art and loads no remote assets. Art, pose mapping, preference storage, controls, and motion styles live in separate modules under `apps/desktop/src/renderer/src/features/mascot/`. It has no network, database, filesystem, or preload access.

The implementation provides three personalities (Professional, Balanced, Playful), randomized short idle blinks/breaths/looks/stretches, sleep and wake reactions, and event-driven poses. Idle motion is timer-scheduled rather than continuous; it pauses for hidden windows, reduced motion, disabled animation, payment entry, and collection reconciliation. It supports pointer-captured dragging from a dedicated handle, keyboard repositioning, minimize/restore, viewport and reserved-lane clamping, theme-aware controls, and optional short sound cues (off by default). Versioned local storage persists position, enabled/minimized state, animation and sound preferences, size, and personality; v1/v2 settings migrate to v3 defaults. Preferences follow the Windows/Electron profile, not an authenticated staff account.

The renderer service layer emits fixed, non-sensitive event names after validated outcomes: subscriber creation, billing start/success/failure, posted payments, verified GCash posting, overdue account search results, report start/finish/failure/cancellation, and backup start/verified completion/failure. A workspace-wide readiness monitor emits connection status changes. No subscriber names, balances, payment amounts, or proof content enter mascot messages. Payment success is emitted only when the validated API result has status `POSTED`; backup success requires a validated `VERIFIED` result.

Use the speech icon (**Talk to BCIS Buddy**) for an on-demand explanation. Messages remain readable for five seconds independently of shorter character poses, unless dismissed or replaced by another reaction. Confirmed outcomes and errors remain visible on payment and reconciliation screens; only ambient behavior is suppressed there. Professional mode still limits nonessential reactions. Repeated confirmed events restart their CSS motion, while reduced motion and disabled animations retain static poses and readable messages.

Higher-priority reactions can interrupt lower-priority ones. Up to four blocked reactions wait briefly (ten-second expiry); the newest phase replaces queued feedback for the same workflow so a completed report never replays its old processing pose. Connection recovery immediately replaces a connection-loss warning. Minimizing, hiding, or leaving the visible window clears deferred feedback. Idle gestures keep their timer cadence during ordinary clicks, while activity resets the sleep timer.

This is a 2D CSS/SVG implementation with a transparent SVG background, not a Rive/Spine rig or frame-by-frame sprite pack. CSS transforms belong to nested layers with explicit pivots in SVG viewBox coordinates. Ambient and event motion use separate wrapper groups; each group has a single transform animation owner. The artwork supports polished 2D posing, but it is not a deforming skeletal rig: elbows, wrists, knees, and fingers do not bend continuously. Walking is limited to the user's drag gesture. The supplied reference guides an original local vector illustration rather than a pixel-matched reproduction.
